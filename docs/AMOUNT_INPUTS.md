# 金额输入验收

0.16.5 排查全部金额构造点，17 个实际金额字段统一使用 `EmptyAmountSpinBox`。提示是 `QLineEdit` 的占位文字，不作为可编辑数值；金额单位放在字段标签、外部货币标识或占位提示中。金额上限、小数位数及业务保存校验保持原有规则。

| 页面／入口 | 金额字段数 | 专项场景 |
| --- | ---: | --- |
| 新增消费、编辑消费及购买确认复用窗口 | 1 | 新建空值、修改已有记录 |
| 月度预算 | 2 | 必要生活、自由消费 |
| 我现在想买：确认商品 | 1 | 未识别价格后手动填写 |
| 执行页：修改金额与用途 | 1 | 零价草稿、小数编辑及实时简报 |
| 记账工作台 | 2 | 手动记账、AI 识别后确认金额 |
| 首次使用设置 | 3 | 两项预算、第一件心愿价格 |
| 价格换算 | 3 | 每日伙食预算、月到手工资、参考商品价格 |
| 商品价格记录 | 1 | 新增／追加价格窗口复用 |
| 心愿新增／编辑 | 1 | 新建空值、修改已有条目 |
| 价格列表目标价 | 1 | 未设置目标价后填写与取消 |
| 心愿价格记录目标价 | 1 | 未设置目标价后填写与取消 |

`amount_input_tests::everyAmountEntry` 使用 19 组页面场景逐项验证：点击空金额后直接输入 123.45，全选替换为 67.89，清空到零，同一焦点内重新输入 9.90，粘贴 29.90，并确认数值有效。不通过 `setValue` 代替用户输入；仅使用它构造初始零价状态。已有消费与心愿另测已有数值的编辑入口。

`typedValuesReachStorageAndZeroKeepsItsMeaning` 验证键盘填写后的预算、真实手动记账、心愿新增／编辑与目标价保存；0 元预算仍可保存，0 元消费仍不可保存，清空目标价继续代表“不设置目标价”。测试只用临时数据库与虚构数据，粘贴测试保留并还原剪贴板的所有 MIME 格式。

执行页另修复实时简报中调用 `interpretText()` 的问题：刷新只读取已更新的 `value()`，不在每个按键后格式化输入框；提交动作仍保留校验和必要的文本确认。否则即使去掉提示文字，也会在输入小数时改写光标和小数位。

账单导入预览中的金额、预算摘要、账单统计、许愿池累计及价格历史是展示值，不新增编辑入口。价格换算的工作天数与工时是普通数值字段，继续保留各自范围与单位。
