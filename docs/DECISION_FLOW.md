# 原版流程迁移 · 第二步

本文记录 0.10.0 的第二步。0.11.0 已继续接入决策辅助、原则与品牌、购买后复盘和蹲价格，当前规则见 WORKFLOW_PHASE3.md。

版本 0.10.0，2026-10-27。原生 C++ / Qt 完成商品输入、确认、忍住／清单／购买三个分支，并接入双预算和许愿池。

## 使用流程

1. 在设置的“AI 商品识别”中填写服务地址、支持图片的模型和个人 API Key，保存。默认地址为千问兼容接口，默认模型 qwen3-vl-plus（0.12.1 起更新）；也可使用兼容的服务。
2. 主页点击“我现在想买……”，输入一句话、选择或拖入商品截图，再点击“解析商品”。解析只产生可编辑初稿，不写入数据库。没有配置 AI 时可点击“手动填写”。
3. 核对商品名、金额、细分类和备注。AI 不知道价格时金额保留为零，须由用户填写；不编造价格。选择购买时还可确认消费日期，选择清单时可调整 1 至 30 天冷静期。
4. 点击一个明确选择：
   - 忍住：只记录忍住金额。有许愿目标时计入该目标，否则先暂存；不生成消费或愿望条目。
   - 清单：保存商品和截图，开始冷静期，不生成实际支出。
   - 购买：直接保存一笔实际消费和截图，更新预算、账单和统计；不强制经过冷静期。

保存失败保留输入，关闭或取消不写入记录。解析中的请求可以取消，过期响应不会写回表单。重复点击不产生多笔消费；忍住记录另有持久化操作编号，失败重试不会重复累计。

## 双预算与分类

在账单页分别设置“基础生活额度”和“可支配额度”，同一次保存；合计仍是月度总预算。每项可以为零，两项合计上限 99,999,999.99 元。支出按消费日期所属月份和细分类计算，与账单筛选无关。

| 细分类 | 预算归属 | 既有六类汇总 |
|---|---|---|
| 食堂 | 基础生活 | 餐饮 |
| 交通 | 基础生活 | 交通 |
| 日用物资 | 基础生活 | 购物 |
| 订阅 | 基础生活 | 其他 |
| 日常（外卖、奶茶、聚餐等） | 可支配 | 餐饮 |
| 网购 | 可支配 | 购物 |
| 娱乐 | 可支配 | 娱乐 |
| 其他 | 可支配 | 其他 |
| 学习（保留旧分类） | 可支配 | 学习 |

旧数据库自动增加字段，不删除记录、改动编号或重写原分类。旧餐饮按日常、购物按网购映射；交通属于基础生活，其余旧分类归可支配。需要更具体的归属时，可编辑记录选择细分类。原六类筛选、分类金额和 B 的分类复盘仍按右列汇总；账单显示具体细分类，悬停可查看预算归属。CSV 追加细分类和预算归属两列。

旧总预算保持未分配状态，不自动猜测两项比例。编辑区暂把旧总额放入可支配输入作为待确认值，并明确提示；用户保存前，数据库仍保留原总额。首页同时展示总余额与两项实际已用／剩余，单项超支也会提示。

## 许愿池

在清单中选中一个待决定愿望，点击“设为许愿目标”。已有暂存忍住金额会一次性计入新目标。目标使用设置时的名称和预计价格快照；后续编辑愿望不自动改写历史目标。

达到目标时显示达标提示；前往清单重新确认是否购买，既有冷静期规则仍生效。目标进度是忍住金额记录，不能当作账户余额或实际收入。进度更新带短动画，可查看最近 200 条忍住记录。

同时只有一个当前目标。切换目标须确认，旧目标和忍住记录保留为历史，不转给新目标；已暂存、尚未指定目标的金额才会计入新目标。购买、放弃或删除对应愿望时，关闭其当前目标；购买状态、实际消费和目标关闭在同一次事务中提交。切换、保存或关闭失败会回滚。

## 截图、设置与备份

截图最多 20 MB、2500 万像素，读取后缩放到最长 1600 像素并编码为不超过 2 MB 的 JPEG。发送 AI 的内容仅包含当前文字和压缩截图。确认进入清单或购买后，压缩截图保存在 SQLite 中；编辑表单可以查看，并在修改时保留。

Windows 使用当前用户的 DPAPI 加密 API Key，写入数据库旁的 `.ui.ini` 设置文件；密钥不存入业务数据库、CSV 或完整备份。服务地址和模型可编辑，不从旧网页的浏览器存储读取凭据。非 Windows 暂不支持持久化密钥。

完整备份包含消费、双预算、愿望、许愿目标、忍住记录及截图。恢复确认显示各类数量，恢复前自动备份当前数据，五张业务表及编号信息在同一次事务中恢复。兼容旧三表备份：仅升级检查用的私有副本，源文件不变；恢复后没有目标或忍住记录，避免残留当前版本的旧状态。

演示仍使用独立临时数据库，示例预算为基础生活 100 元、可支配 200 元；目标为机械键盘，已攒忍住金额 45 元。演示中设置的密钥也只保存在临时目录，退出后删除。正式模式中的设置会保留。

## 验证与边界

decision_tests 通过本机 HTTP 模拟服务验证实际 Qt 网络请求、图片编码、响应校验、密钥错误及取消；同时验证真实界面的三个写入分支、双预算、目标切换和购买事务、旧备份与完整恢复。未使用个人真实 Key，不产生模型费用；真实千问及其他服务的模型权限和网络可用性需在填写 Key 后实际确认。
