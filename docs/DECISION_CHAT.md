# 决策助手对话界面

2026-10-28，按已确认的米白对话样板更新原生 C++／Qt 界面。

`DecisionChatWidget` 负责消息、输入与交互，`ExecutionWidget` 继续负责真实预算上下文、AIService 请求、会话和购买流程。

- 用户消息显示在右侧浅色气泡，助手消息在左侧分段显示。
- Markdown 的标题、强调和列表正常排版。长回复的补充分析默认折叠，复制时包含完整内容。
- 回复随页面增高，不嵌套一层回复滚动条。输入与发送位于同一区域，支持 Enter 发送、Shift+Enter 换行和中文输入法组合输入。
- 生成期间显示「停止」，停止或请求失败后保留问题并提供重试；原有回答保留。重新回答只替换最后一条回答，不重复添加用户消息。
- 不展示内部简报提示词。未开始对话时可主动请求分析，或使用预算问题入口；不会在打开页面时自动调用 AI。
- 支持多轮对话。请求携带最多最近 8 条、合计不超过 24,000 字的历史消息；当前问题仍最多 2,000 字，服务响应仍最多 8,000 字。

会话记录继续使用已有 `execution_sessions.advice` 文本列，以带版本号的 JSON 保存多轮消息和草稿，兼容旧版单轮纯文本。不新增数据库字段；会话存储与备份校验共同将对话长度上限由 12,000 提升为 128,000 字，避免第二轮长回复就无法保存。完整备份保留聊天记录。

商品、预算或原则更新时会取消正在生成的旧请求，并清空旧上下文中的对话，后续回答读取新事实。重新启动、结束决策或恢复备份时同样取消旧请求，迟到响应不会覆盖新的界面状态。

测试使用本机 HTTP 模拟服务和隔离数据库，不读取正式账单或调用真实付费模型。`decision_chat_tests` 覆盖消息排版、键盘和输入法、复制与展开、旧数据兼容、多轮真实 HTTP 请求、重新回答、失败与重试、取消迟到响应、重启／备份恢复，以及暖色／冷色／深色与小窗口布局。截图位于 `build/preview/decision-chat-*.png`。

验证结果：6 个对话场景全部通过，包含初始化与清理共 8 项通过；7 组相关回归全部通过。最后调整首屏高度后，又通过对话专项及执行／工作流／外壳三组回归。在 PATH 仅包含独立运行目录与 Windows 系统目录的环境下，对话专项和程序版本命令也均正常退出。
