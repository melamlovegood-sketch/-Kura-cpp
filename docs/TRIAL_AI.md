# 小组 AI 试用

Windows 结对测试包可提供项目方明确授权的共享 AI 服务。0.16.2 导出的试用配置带 `defaultForNewUsers: true`，未配置 AI 的新用户默认选择试用，新手引导显示“已选择 Kura AI 试用”，无需填 Key 即可确认下一步。启动和保存均不会发送请求。设置中可以切换“使用自己的 API Key”，明确选择会保存，不被默认试用覆盖；旧个人 Key 也不会被自动切走。旧试用配置缺少默认标志时仍由用户主动启用。个人配置与试用配置分开；个人密钥继续用 Windows DPAPI 在本机保存，不进入业务数据库或备份。试用密钥不填入个人输入框。

所有 AI 功能共用当前选择：商品解析、截图记账、价格与商品详情提取、商品和决策讨论、账单分类、月度故事。连接测试同样使用当前选择，最近测试结果按实际配置隔离。试用被服务商拒绝时提示试用暂不可用或已结束；额度不足时提示稍后重试或切换个人 Key。不自动回退到个人凭据，不自动重试真实请求。普通记账、清单和本地数据继续可用。


个人配置下方提供阿里云百炼官方申请入口及可展开的申请教程，说明北京地域、模型免费额度与用完即停，再指导回到 Kura 保存和测试。详见 [千问 Key 申请与填写](QWEN_API_KEY_GUIDE.md)。

## 生成测试包

项目方在自己的正式应用中保存 AI 服务地址、模型和 Key 后，运行：

```powershell
./scripts/Build-Unified.ps1 -IncludeTrialAI
```

若本机刚重置且原 AI 配置在本地备份中，可使用 `-TrialAISettingsPath 'C:/path/to/kura.sqlite.ui.ini'`，仅从指定设置文件读取并导出 AI 服务配置，不复制设置文件或数据库。先运行常规 `Build-Unified.ps1` 验证新版，再带试用参数运行时可复用同一源码已验证的二进制与完整测试日志。最后用 `Build-Installer.ps1 -IncludeTrialAI` 生成名称含 `AITrial` 的安装程序；其使用说明与普通包分别生成。

脚本仍需通过编译、全部回归及源码指纹校验，使用独立 `LOCALAPPDATA/KuraBuild/build-trial-ai` 构建目录并遵守发布锁。若固定入口指向的当前运行包与源码指纹完全一致、程序哈希正确且完整日志记录了全部测试通过，则复用这份已验证程序与日志生成试用版本；否则重新编译并完整回归。然后调用已构建程序的 `--export-trial-ai`，只将当前本机保存的个人 AI 配置导出到运行包内的 `kura-trial.json`；不导出个人账本或整个设置文件，不打印密钥，不发起真实 AI 请求。运行包包含试用说明。常规发布不带该文件。

共享配置必须可被其他电脑读取，因此它不是 Windows DPAPI 文件，随包凭据可被提取，不应视为安全隐藏。仅分发给结对测试小组；宜使用专门的测试 Key，按服务商支持情况配置额度或预算限制。测试结束后在服务商后台撤销该 Key，单靠关闭入口或删除本机文件无法撤销其他人已有的副本。此文件已加入 Git 忽略规则，不写入源码、资源或日志。

## 验证

`trial_ai_tests` 仅使用本机模拟服务和虚构密钥，覆盖主动启用、重启保持、个人配置保留、缺失／损坏／无效共享配置、禁止隐式回退、文字与截图请求、401 停用和 429 额度错误。完整发布继续运行项目全部测试。
